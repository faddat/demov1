NUNCHI BRIDGE

Verify, then admit.

The original BridgeActor::verify_payload and submit method bodies are extracted unchanged from the pinned SDK source and compiled through a synchronous browser adapter. They check the foreign certificate and compare its view to the latest accepted view.

DKG TYPES / COMMONWARE CRYPTOGRAPHY

Real certificates. Test setup.

The same threshold Scheme and Finalization types used by Nunchi DKG sign three fixture shares, assemble a BLS12-381 certificate and verify it with original Commonware code. The public test setup supplies the shares; a distributed DKG ceremony is not run here.

THE APPLICATION

Make the flow visible.

The application supplies the two local network models, synthetic proposal data, relay queue, playback, 3D islands and inspector. Authority, Chain, RPC, Mempool and node processes are not executed in this browser example.

Why would a developer build this?+

Use external chain information.

An application may need to react to what a separate network finalized. A signed certificate provides evidence to check against a configured foreign network.

Reuse the hard primitives.

Developers can compose existing certificate verification, encoding and bridge admission logic with their own chain runtime, relayer and business rules.

Define the trust boundary.

The application still chooses the foreign network and how to act on accepted information. This example demonstrates certificate verification, not a universal token bridge or an arbitrary claim about another chain’s state.

Simulation Assumptions & SDK Details+

What runs here

SDK 2026.9.0-alpha.1, commit eea35ced709f68c15d6fbc8bcc754696a7e44374; Commonware 2026.9.0. Two independent local test committees with four shares each. Certificate generation, cryptographic verification and latest-view admission run newly in browser WebAssembly.

Reset creates fresh session-derived test keys and empty state. These are public deterministic demo identities.

What “accepted” means

The certificate passed the receiver’s configured foreign-network verification and had a newer view than its cache. The accepted view updates local session memory. A valid repeat or older view is stale.

Chain heights are fixture proposal counters, not observed node heights. Synthetic block payloads are hashed and signed. Consensus networking, actual finality, QMDB inclusion/state-root proofs, epoch/key rotation and persistent storage are outside this demo.

Execution boundary

The browser adapter executes the original BridgeActor verification/admission bodies without spawning its async actor. Full BridgeExtension block integration is not executed. Original source hashes, adapter source and WASM fingerprints are provided.

No asset transfer, swap, external chain, public-network settlement, or live validator network is deployed. 256 certificates per local session. Export verification checks the included local command replay, not historical completeness.
